普段 Claude Code でスマホアプリを個人開発しています。

最初は Cursor 上で Claude Code を使っていたのですが、ある日気づきました。**これ、めちゃくちゃ使いにくい。**

## Cursor + Claude Code の何が辛かったか

- Claude Code の完了に気づけない（ずっと画面を見ていないといけない）
- 複数プロジェクトを並行開発すると、どのセッションが完了したか毎回探している
- Cursor のウィンドウをプロジェクト数分開いていて、Mac が重い

要するに「**Claude Code を走らせながら別のことができない**」という問題です。

せっかく AI がコードを書いてくれているのに、自分も画面を凝視していたら意味がありません。

## 解決策：ターミナルを本拠地にする

試行錯誤した結果、今はこの構成に落ち着きました。

| ツール | 役割 |
|--------|------|
| **cmux** | 複数セッション管理・通知リング |
| **yazi** | ファイルツリー表示 |
| **lazygit** | Git 操作 |
| **Raycast** | アプリ起動ショートカット |
| **Cursor / VSCode** | Flutter ビルド・詳細なコード確認（補助）|

---

## cmux：これがすべての起点

@[card](https://cmux.com/ja)

cmux は **複数の AI コーディングエージェントを同時に走らせるために設計されたネイティブ macOS ターミナルアプリ**です。Swift + AppKit 製で Electron ではないため軽量で、Ghostty ベースの GPU 高速レンダリングが使えます。

### なぜ cmux か

cmux を使うと、**サイドバーに git ブランチ・作業ディレクトリ・通知をまとめて表示しながら**、複数セッションを管理できます。プロジェクトごとにセッションを分けておけば、Claude Code を複数プロジェクト同時に走らせていても整理された状態を保てます。

```
┌─────────────────────────────────────┐
│  セッション: project-A               │
│  Claude Code 実行中...               │
├─────────────────────────────────────┤
│  セッション: project-B               │
│  Claude Code 完了 ✓  ← バッジ表示   │
├─────────────────────────────────────┤
│  セッション: project-C               │
│  Claude Code 実行中...               │
└─────────────────────────────────────┘
```

### 通知リング機能

cmux にはエージェントが入力待ちになると**ペインが点灯してサイドバーにバッジが表示される**通知リング機能が内蔵されています。Mac の通知センターにも通知が出るので、画面を見続ける必要がなくなりました。

### セッション切り替えショートカット

完了通知が来たら、すぐそのセッションに飛べるショートカットを設定しています。

```
⌘ + Shift + U → アラートのあるセッションへジャンプ
```

## yazi：Claude Code へのファイルパス渡しが快適に

@[card](https://github.com/sxyazi/yazi)

ターミナル上で動くファイルマネージャーです。Claude Code に「このファイルを修正して」と伝えるとき、正確なファイルパスを渡す必要があります。yazi があるとキーボードだけでファイルを選択して、パスをコピーできます。

### 横長にならない設定

デフォルトだと 3 ペイン表示で横に広がりすぎるので、現在のディレクトリだけを表示する設定にしています。

```toml
# ~/.config/yazi/yazi.toml
[manager]
ratio = [0, 1, 0]  # 親・現在・プレビューの比率
```

---

## lazygit：ブランチと worktree の管理が一目瞭然

@[card](https://github.com/jesseduffield/lazygit)

Claude Code は worktree を活用した並行開発と相性がよいです。lazygit を使うと、どの worktree でどの作業が進んでいるかを視覚的に確認できます。

特に便利なのが以下の 2 点です。

- **ブランチ一覧**：Claude Code が作成したブランチがすぐ確認できる
- **worktree 管理**：`w` キーで worktree の一覧・切り替えができる

---

## Raycast：通知から作業復帰までを 1 アクションに

@[card](https://www.raycast.com/)

ターミナルを開くショートカットを設定します。

```
⌘ + Shift + C → cmux（ターミナル）を前面に出す
```

C は cmux の頭文字から取っています。

### 通知が来てから作業に戻るまでの流れ

```
① Mac 通知「Claude Code 完了」が右上に表示される
② ⌘ + Shift + C でターミナルをフォーカス
③ ⌘ + Shift + U で完了セッションにジャンプ
④ 結果を確認して次の指示を出す
```

**この 3 ステップで、ノーストレスで Claude Code の結果に辿り着けます。**

---

## Cursor / VSCode は「補助」として残す

完全にターミナルに移行したとはいえ、IDE は捨てていません。

- Flutter の実機ビルド・ホットリロード
- 複雑な差分を視覚的に確認したいとき

この 2 つは今も IDE に頼っています。将来的には Flutter のビルドもターミナルから操作できる構成にしたいと思っています。

---

## Before / After

**Before（Cursor + Claude Code）**
- 複数 Cursor ウィンドウを開いて Mac が重い
- 完了を気づくために画面を見続ける
- どのセッションが完了したか探し回る

**After（ターミナル中心）**
- cmux セッションで整理されて軽い
- 通知が来るまで他の作業ができる
- ショートカット 2 回で完了セッションへジャンプ

---

## まとめ

Claude Code を使うなら、**IDE に縛られる必要はありません**。

ターミナルを整備するだけで「AI がコードを書いている間、自分は別のことができる」という状態を作れます。必死でセッションを追いかけていたあの頃に戻りたくない。

気になるツールがあれば、まず 1 つだけ試してみてください。個人的には **cmux の通知リング**が一番インパクトが大きかったです。

皆さんの Claude Code 活用術や開発環境もぜひ教えてください！
